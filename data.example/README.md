# 数据模板说明（data.example）

本目录是**演示数据模板**，不包含任何真实账号的领取记录。应用运行时的数据不在这里，
存在服务端数据库里（见文末「数据到底存在哪」）。这个模板的作用是：让你看清台账的
数据结构长什么样，并照着把目录换成你自己的。

## providers.example.json —— 平台目录（39 家示例）

应用内置目录在 `server/src/actions.ts` 的 `CATALOG` 中（服务端动作 `syncCatalog`
会把它同步进数据库）。本 JSON 是同一份目录的导出副本，方便你在不动代码的前提下
先看、先改、先规划你自己的目录。字段逐项说明：

| 字段 | 含义 | 换成你自己的时怎么做 |
|---|---|---|
| `name` | 平台显示名（中文为主），台账按名去重 | 改成你实际在用的平台名 |
| `nameEn` | 英文名（可空） | 没有就留空字符串 |
| `backer` | 背后的公司/组织 | 写平台运营方 |
| `group` | 分区：`api`=API 能打水 / `compute`=免费VPS / `efficiency`=提效工具 / `tool`=工具福利 | 四选一 |
| `quotaText` | 卡面价值句：一句话说清「对你有什么用 + 额度」 | 用你自己的话重写，别照抄别人的体验 |
| `content` | 详情正文：额度细节、刷新规则、注意事项 | 按你核实到的官方政策写 |
| `cycle` | 周期文案：每日/每周/每月/一次性/长期等 | 按官方规则写 |
| `sortValue` | 排序基数（面值或日量），入库时按 `valueKind` 换算成「实际可用价值」排序 | 填额度面值即可 |
| `valueKind` | 可选：`daily` 每日刷新（×30）/ `weekly` 每周（×30/7）/ `voucher` 代金券（×0.5）/ `free` 免费不限量；缺省=一次性面值 | 按额度性质选 |
| `featuredRank` | 可选：左列「大羊毛推荐」名次（1 起，缺省不上榜） | 给你最看重的几家排 |
| `demoOnly` | 可选：示例专属条目——只在示例状态下入账展示，用户添置第一件自己的战利品、看板翻转到自己的状态时随示例清场删除 | 模板里有「示例云电脑」「示例海外服务器」两张演示此机制，换成你自己的服务器卡或直接删掉即可 |
| `status` | **领取状态（个人记录）**：`unclaimed` 未领 / `registered` 已注册 / `pooled` 已入池可用 / `claimed` 已领 / `check_old` 待验旧号 | 模板里全部是 `unclaimed` 示例值——**必须换成你自己的真实状态** |
| `keyTail` | **API key 尾号（个人记录）**，仅供自己辨认，永不存完整 key | 模板为空；你只填尾号，完整 key 不要写进任何文件 |
| `note` | **备注（个人记录）** | 模板为空，写你自己的备忘 |
| `taskCycle` | 定期处理周期：`none` / `daily` / `weekly` / `monthly`（到期红点按它算） | 哪家需要你定期处理就给哪家设 |
| `taskLastDoneAt` | **上次处理时间（个人记录）** | 模板为 `null`；应用会在你点「完成」时自动写 |

带「个人记录」的四项（`status` / `keyTail` / `note` / `taskLastDoneAt`）就是你必须
替换成自己数据的部分；其余是平台公开信息，可沿用也可增删改。

## 截图演示说明

README 的截图是用本模板在本地跑起来的演示实例截的：目录与本模板一致，另外把
魔搭社区、Cloudflare Workers AI、OpenRouter、硅基流动等几家的 `status` 在演示库

## 网关调用统计（可选）

补给泵图下层水源的「近 7 天调用」数据来自服务端表 `gateway_stats`（结构见
`drizzle/0005_add_gateway_stats.sql`），由外部任务把 new-api 网关日志按渠道聚合后
调用服务端动作 `syncGatewayStats` 写入。不接网关时该表为空，泵图自动按额度绘制，
不影响其他功能。

## 示例状态（board_mode）

全新安装从「示例状态」起步：甲板展示内置示例数据（就是本目录这份），页面顶部有
横幅明确标注示例。示例状态下你在页面上点亮一家、改一家、或新增一家，都算
「添置了自己的战利品」——应用会自动翻转到你自己的状态：你动手的那一行保留，
其余示例数据复位成一张干净的待领取目录，示例专属条目（`demoOnly`）直接删除，
此后不再回到示例状态。状态存在服务端 `settings` 表的 `board_mode` 一行里
（迁移 `drizzle/0006_add_settings_table.sql` 按存量数据定初始值）。

## 数据到底存在哪

- Muse Space 运行时：数据存应用自己的数据库（本工程为 SQLite `app.db`，
  由宿主管理），**不要把真实数据库文件提交进任何公开仓库**（`.gitignore` 已排除）。
- 目录（CATALOG）是代码的一部分，改目录 = 改 `server/src/actions.ts` 后重新部署，
  下次打开页面时 `syncCatalog` 会把新目录同步进你的台账（只补缺、补结构字段，
  不覆盖你的状态、备注与 key 尾号）。
